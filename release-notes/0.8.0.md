Postino 0.8.0 improves imports: the workspace is now the destination of an import, chosen inside the wizard, and Postman collections go through the same wizard.

## What changes

### New

- **Postman goes through the import wizard** (#211): collections, environments and globals, from one or several files, pasted text, a folder or a `.zip` data export, with the format detected from the content. Choose the environments and what to convert, review the requests with what converts and what does not (complete, with warnings, unsupported), and get a report in `.postino/import-report.md`. Dropping a file on the window opens the wizard.
- **Update a collection from a new Postman export** (#212): a new export of a collection you already imported is recognized by its id, and the Preview lists what was added, changed or removed, as for OpenAPI. Changed requests keep your scripts, tests and edited values.
- **Choose the destination inside the import wizard** (#208): the Options step of the import wizard has a Destination block. With no workspace open it proposes a new one, named after the API, in `Documents/Postino`, so the first import is Next, Next, Import. With one open you can keep it, pick a recent one, create one or use any folder. It warns as soon as a name is taken, the folder already is a workspace, has other files or cannot be written. A folder source can become the workspace itself. Nothing is written until you confirm, and a failed import removes what it created.
- **Multipart bodies and file uploads** (#209): the new Multipart body type sends `multipart/form-data`. A value that starts with `@` uploads a file, with relative paths starting at the workspace folder. In a file it is `::: body multipart`. OpenAPI multipart operations now import as multipart, not as URL encoded forms.
- **Postman scripts are converted** (#210): `pm.test`, `pm.expect`, `pm.response`, `pm.environment`, `pm.collectionVariables`, `pm.globals` and `pm.variables` become Postino's script API. What has no equivalent, such as `pm.sendRequest`, stays as a comment, and the rest of the script runs. Form-data bodies import as multipart, OAuth 2.0 access tokens as a bearer token, and collection variables are copied into every environment.

### Polish

- **Shorter names for imported environments** (#207): an OpenAPI import with several servers names each environment after the server, not after the collection and the server. Long environment names no longer push the buttons of the environment editor out of the window, or run under the delete button of its table.
