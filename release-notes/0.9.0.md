Postino 0.9.0 is in progress.

## What changes

### New

- **Import from Bruno** (#213, #221, #222): Bruno collections, in `.bru` files or the OpenCollection YAML of Bruno 3.0, go through the import wizard, from their folder, a `.zip` or loose request files. Requests, folders, inherited headers and auth, GraphQL requests (as JSON bodies) and environments convert, with their colors. Scripts, tests, `assert` blocks and request variables are converted to Postino's script API; what has no equivalent stays as a comment. Secrets, which Bruno keeps on each machine, are created empty in `.local.env`. The Bruno folder is never changed.
- **Update a collection from Bruno** (#223): importing a Bruno collection already imported, from its folder or a `.zip`, offers to update it: the Preview lists what was added, changed or removed, and changed requests keep your scripts, tests and edited values.
- **Workspace configuration file** (#215): `.postino/project.toml` holds the settings that belong to the workspace and are shared through git, starting with the order and colors of the environments. It is optional: a workspace without it works as before, and it is created with a new workspace or the first time you change something it holds.
- **Choose the color of an environment** (#217): click the dot next to the name in the environment editor, or choose Color… in its menu, and pick one of nine colors or Automatic, the color from the name as before. The color shows in the panel, the editor, the environment picker and the command palette, and is saved in `.postino/project.toml`.
- **Reorder environments** (#216): drag an environment in the Environments panel by its grip, or use Move up and Move down in its editor (`Alt+Up` and `Alt+Down`). The order applies to the environment picker, the command palette and the `Ctrl+1` to `Ctrl+9` shortcuts, and is saved in `.postino/project.toml`.
- **Refresh collections** (#219): a button in the Collections header, and a command palette action, read the workspace from disk again, to show changes made outside Postino, such as a `git pull` in a terminal.

### Fixes

- **Discarding changes refreshes the sidebar** (#218): discarding local changes in the Source Control panel, or reverting a block in a diff, now reads the workspace again, so a discarded new request leaves the collections tree and a restored one comes back, as after a pull.
